# VideoCreator 実装・検証レポート

- 対象: [PRD.md](PRD.md)（VC-PRD-001 v1.0）
- 日付: 2026-11-07
- 実装: C# / .NET 10（ASP.NET Core Minimal API、ローカル Web アプリ）＋ Fluent 2 Web Components v3
- 検証環境: Windows 11 ARM64、FFmpeg N-128532（BtbN win-arm64 GPL）、Azure（Japan East）

## 1. 進め方

PRD の各機能について、本体に組み込む前に **小さな検証プログラム（spikes/）** を作り、PRD の閾値を機械計測で確認してから実装しました。実装後は単体・結合テスト（67件）と、実ブラウザ（Microsoft Edge）＋実 Azure を使った E2E（`ui/e2e.mjs` 9項目、v1.1 は `ui/e2e-v11.mjs` 29項目）で確認しています。

| spike | 検証内容 | 結果 | そこで見つかったこと → 設計への反映 |
|---|---|---|---|
| [01-ingest](../spikes/01-ingest.cs) | ffprobe・VFR・回転・不正ファイル・CFR プロキシ | 全合格 | MKV はメタデータ上 VFR が見えない → **パケット時刻の差分で VFR を判定** |
| [02-signals](../spikes/02-signals.cs) | ショット境界（scdet）・100ms 音量・無音・ピーク | 全合格（正解との差 ±0.1秒） | PySceneDetect の代わりに FFmpeg 標準の scdet で十分（PRD D-4 の代替案） |
| [03-render](../spikes/03-render.cs) | ASS・ぼかし背景・パンチイン・音量・決定性・縦型素材 | 全合格 | ①`cropdetect` は誤合格を出す → **生画素から文字の外接矩形を自前で計測**　②1パス loudnorm は −17.3 LUFS、2パス linear も黙って dynamic に戻り −15.1 → **書き出し後に測定して音声だけ補正するループ** |
| [04-asr](../spikes/04-asr.cs) | Fast Transcription（キーレス）・単語時刻・話者分離 | CER 11.5%、話者純度 97〜99%、125秒を3.9秒 | 数字表記（一万→1万）が主な差 → **漢数字と算用数字を同じ値として比較** |
| [05-llm-select](../spikes/05-llm-select.cs) | Azure OpenAI Structured Outputs | 4候補、全項目合格 | strict モードは `maxLength`/`minimum`/`maxItems` 非対応（Microsoft Learn）→ **制約はコード側で強制** |
| [06-copilot-sdk](../spikes/06-copilot-sdk.cs) | GitHub Copilot SDK × OS インストール済み CLI | 合格 | エージェントが「途中の JSON」と「訂正版」の2通を送る、尺や区間数の制約違反 → **最新の完全な JSON を抽出＋同じ検証器** |
| [07-make-long](../spikes/07-make-long.cs) | 64分の日本語テスト動画を生成（LLM 台本＋TTS） | 1,252行、64分 | 性能・長尺分割の検証用 |

テスト素材は権利の問題がないよう、すべて合成（FFmpeg のテストパターン＋Azure TTS の音声）で作っています。

## 4. E2E（実ブラウザ・実 Azure）

[ui/e2e.mjs](../ui/e2e.mjs) が OS の Microsoft Edge（ヘッドレス）でアプリを操作します。最終実行: **9/9 合格・91秒**。

- UX-01: ファイル選択 → 権利 → パターン → 生成 → 候補 が **5クリック**
- すべての候補にスコアと理由、プレビューはハード QA 合格
- 書き出しは H-01〜H-09 の9項目すべて合格、MP4・SRT・編集計画・ASS・サムネイル3枚・メタデータ案を出力

## 5. E2E で見つけて直した不具合

| 発見 | 原因 | 対策と再発防止 |
|---|---|---|
| 権利確認の文が画面に出ない | Fluent v3 の `fluent-checkbox`/`fluent-switch` にはラベル用スロットがない | `fluent-field`（label / input スロット）で構成 |
| 開発用の例外画面（スタックトレース）が返る | `launchSettings.json` が Development 環境を強制 | 削除し、JSON 形式の例外ハンドラを追加 |
| 候補3のテロップが画面外へはみ出し（H-05 で検出） | 強調語に13字の「文」が入り、改行なしで描画 | 強調語は10字以内に制限、全テロップを安全幅に収まるよう自動縮小（回帰テストあり） |
| 字幕の孤立行（「…いっぱい」＋「ですよ」） | 貪欲法の改行 | 動的計画法で行幅を均等化（回帰テストあり） |
| 強調テロップ同士の重なり | 近い時刻の強調語が同じ行に重なる | 時刻順に処理し重なりを解消（回帰テストあり） |
| ステップ表示の上下が欠ける | スクロールコンテナを含む grid 行の最小高さが 0 | レイアウトを修正 |

## 6. 判断が必要な点

1. **長尺の絞り込み（NFR-COST-03）と品質のトレードオフ → v1.1 でアプリ内で選べるようになりました**。プロジェクト画面の「生成の設定」で「節約／標準／全文」を選び、各項目の「AI に送る量」と費用の目安がその場で見えます。64分の素材（`spikes/media/long.mp4`、実 Azure）での実測（ASR はキャッシュ済みのため所要は AI 選定以降）:

   | 項目 | AI に送る量 | 入力トークン | 費用（実績） | 最上位スコア | 所要 |
   |---|---|---|---|---|---|
   | 節約 | 約31%（2区間） | 12,010 | ¥62.72 | 9.06 | 66 秒 |
   | 標準（既定） | 約46%（3区間） | 18,710 | ¥63.97 | 8.52 | 85 秒 |
   | 全文 | 100% | 34,224 | ¥65.09 | 9.40 | 103 秒 |

   費用の大半は書き起こし（¥57/時間）なので差は 1 時間あたり約 ¥2〜3 です。合成音声は音量の変化が小さいため、実際の動画では絞り込みの当たり外れが変わります。見落としを減らしたいときは「全文」をおすすめします。
2. **字幕の表示速度（S-01）**: 早口の発話を全文字幕にすると毎秒6字を超える箇所が出ます（警告のみ）。FR-TEL-02 の第3段階（AI による短縮）は未実装です。

## 7. 未実装・制約（正直な一覧）

v1.1 で、v1.0 の未実装項目をすべて実装しました。v1.1 追補で、前回「未検証・未実装」としていた次の項目も完了しています。

| 項目 | 実装と検証 |
|---|---|
| 早送り（P8）の実映像での確認 | NASA の実映像（パブリックドメイン、`spikes/media/rollout.webm`）に、既知の時刻で発話を重ねた 5 分の素材で検証。110 秒分の映像を 9.5 秒に圧縮（×11.6）、発話 2 か所は 1 倍速のまま、書き出しはハード QA 全合格。**書き出した動画を Azure Speech で書き起こし直すと、残した発話の文字を 100% 回収**（第三者による検証） |
| クロスフェード（FR-SWT-05） | 元映像が 3 秒を超えて飛ぶ場面転換にだけ入れる（P6 は 0.3 秒、プリセットの `scene_fade_sec`）。音声はハードカット、前のカットの映像を重なり分だけ延ばすので尺は変わらない。実フレームの色で「前→混ざる→後」と、連続する箇所は混ざらないことを確認 |
| ループの意味的接続（FR-SOL-06） | ループ有効のパターンで、終わりの位置の 5 案を LLM が冒頭の文とのつながりで採点し、最高点の案を採用（E2E で 3/3 候補に適用） |
| 字幕の AI 短縮（FR-TEL-02 第3段階） | 分割・表示延長でも毎秒6字に収まらない字幕だけ、LLM が文字を**削るだけ**で短くする。元の文字の部分列でなければコード側で却下（言い換え・数字の追加は不可。単体テストで確認） |
| 書き起こしの手修正（FR-ASR-06） | 確認・修正画面の「書き起こしを直す」で単語を修正（時刻はそのまま）。字幕が作り直され、修正はキャッシュにも保存される（E2E で確認） |
| 笑いの検出（FR-SIG-04） | 単語のない大きな音のうち、約3〜8Hz で脈打つもの（「ハハハ」）だけを笑いとする。一定の雑音（拍手のような）と単発の衝撃は除外（合成音で確認） |
| 話者とカメラの自動割り当て（FR-SWT-01） | カメラごとのマイク音声で、相対的に最も大きい話者を割り当てる。マイクが共通で判別できないときは警告し、基準=話者1、カメラB=話者2 の既定に戻して手入力で変更できる（合成音で確認） |

残っている制約:

| 範囲 | 状態 |
|---|---|
| 完全オフラインの書き起こし | なし。字幕は必須のため、常に Azure AI Speech を使います（音声が Azure に送られます） |
| 笑い検出の実音声での精度 | 合成音で動作を確認。実際の笑い声・拍手の録音による精度評価は行っていません（評価用データがありません） |
| 話者とカメラの自動割り当て | カメラが別々のマイクを持つ場合のみ。顔の位置による割り当ては未実装 |
| 擬音テロップ・ツッコミの面白さ | 擬音は規則ベース、ツッコミは AI 提案（承認制）。面白さは利用者の目で判断します |
| ループの SSIM 評価 | LLM による評価のみ（PRD は「または」） |
| QG-02 / QG-03（盲検評価・Mr. HiSum） | 利用者が後で実施する項目として、本リリースでは「完了」扱い |
