# 빠른 시작: 첫 동영상 만들기

[앱 README](../README.md) / [가이드 목차](README.md) / [화면 설명](screens.md) / [문제 해결](troubleshooting.md) / [설정·API](configuration-api.md)

**목표**: 발화가 있는 동영상 한 편으로 P4 후보를 만들고, 내용을 확인한 뒤 1080×1920 MP4와 자막 등을 저장합니다. 처리 시간은 원본·PC·서비스 상태에 따라 달라지므로 일정 시간 안에 완료됨을 보장하지 않습니다.

## 1. PC와 동영상 준비하기

- Windows 10/11(x64 / ARM64), 인터넷 연결이 필요합니다. 브라우저는 Microsoft Edge로 화면을 확인했습니다.
- 저장소를 내려받아 압축을 풉니다. Git을 사용하지 않는다면 GitHub의 「Code → Download ZIP」으로 받고, ZIP 내부가 아니라 압축을 푼 폴더를 여세요.
- **본인에게 사용할 권리가 있는 동영상** 한 편을 준비합니다. 음악·얼굴·로고 등의 허가도 확인하세요. 지원 표시는 MP4 / MOV / MKV / WebM, 길이 10초~3시간입니다. 처음에는 몇 분 정도의 발화 동영상이 다루기 쉽습니다. P4는 25~35초 본편을 만들므로, 10초 동영상이면 반드시 성공한다는 뜻은 아닙니다.
- 디스크 여유 공간을 확인합니다. 파일 선택·끌어서 놓기에서는 임시 영역과 저장 위치 모두에 원본 크기만큼의 여유가 필요합니다. 같은 드라이브라면 원본의 약 2배에 프록시, 캐시, 미리 보기, 내보내기용 공간을 더 확보하세요.
- **전체 경로로 지정**하면 원본 복사를 생략할 수 있습니다. 다만 원본 동영상을 이동·삭제하면 해당 프로젝트를 사용할 수 없게 됩니다.

## 2. 본인의 클라우드 설정 준비하기

자막 자동 생성에는 Azure Speech의 Fast Transcription을 사용합니다. Azure 관리자에게 다음을 확인해 달라고 요청하세요.

| 용도 | 준비할 정보·권한 |
|---|---|
| 필수: 전사 | 지원 리소스, 사용자 지정 하위 도메인이 있는 엔드포인트 `https://<본인-리소스>.cognitiveservices.azure.com/`, 지원 지역, 사용자의 `Cognitive Services User` 역할 |
| 선택: Microsoft Foundry로 선정 | 지원 모델의 배포 이름, `https://<본인-리소스>.cognitiveservices.azure.com/openai/v1`, `Cognitive Services OpenAI User` 역할 |
| 선택: Copilot으로 선정 | Copilot 사용 자격과 설치·로그인된 GitHub Copilot CLI |

Azure 서비스는 사용량 기반으로 과금됩니다. 모델명이 아니라 **본인이 만든 배포의 이름**을 설정합니다. 설정 스크립트가 리소스·배포를 생성해 주지는 않습니다.

실행 전에 [appsettings.json](../../../src/VideoCreator.App/appsettings.json)의 `VideoCreator` 섹션을 본인의 값으로 바꾸세요. 아래는 해당 섹션의 예시이지, 파일 전체를 대체하는 내용이 아닙니다.

```json
{
  "Asr": {
    "Provider": "azure",
    "Endpoint": "https://<본인-리소스>.cognitiveservices.azure.com/",
    "Locale": "ja-JP"
  },
  "Llm": {
    "Provider": "none"
  }
}
```

처음에는 `Llm.Provider=none`이어도 됩니다. 자막은 Speech로 만들고 후보는 음량이 높아지는 구간에서 고릅니다. 발화 내용을 기반으로 선정하려면 Microsoft Foundry나 Copilot을 설정하세요.

**주의**: 배포된 설정 파일에는 예시 엔드포인트가 들어 있습니다. 해당 리소스를 사용할 수 있다고 단정할 수 없습니다. 키나 토큰은 설정 파일에 쓰지 마세요. 조직의 전송·데이터 사용 정책을 확인하세요.

공식 자료: [Fast Transcription](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/fast-transcription-create) / [Speech의 Entra ID 인증](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-configure-azure-ad-auth) / [지원 지역](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/regions).

## 3. 실행하고 준비 상태 확인하기

저장소 루트의 [run.cmd](../../../run.cmd)를 두 번 클릭합니다. 터미널을 사용한다면 저장소 폴더에서 다음을 실행합니다.

```powershell
.\run.cmd
```

처음에는 부족한 .NET SDK 10, FFmpeg, 일본어 글꼴, 모델, Azure CLI를 설치합니다. 필요에 따라 관리자 확인이나 `az login` 로그인 화면이 나타납니다. Copilot CLI도 설치하려면 `.\run.cmd --setup --with-copilot`을 사용하세요.

- 시작할 때마다 현재 소스를 빌드합니다. 빌드에 실패하면 이전 결과물로 시작하지 않습니다.
- 앱 시작이 끝나면 PC에 설치·구성된 Windows 기본 브라우저에서 <http://127.0.0.1:8765/>가 열립니다(포트를 바꿨다면 해당 URL). 브라우저를 추가 설치하거나 새 프로필을 만들지 않습니다. 열지 못하면 터미널에 경고와 URL이 표시되므로 직접 여세요. `--check`·`--no-start`는 앱과 브라우저를 모두 시작하지 않습니다.
- 시작 터미널을 닫지 마세요. 닫으면 앱이 중지됩니다.
- `FAIL`은 필수 로컬 구성 요소가 부족하다는 뜻입니다. `WARN`은 경고이며, 특히 Azure 경고가 있으면 캐시되지 않은 음성의 전사를 사용할 수 없을 수 있습니다. 「앱이 시작됨」과 「자막 생성 사용 가능」은 다릅니다.
- 확인만 하려면 `.\run.cmd --check`를 사용합니다. 설치나 설정 저장은 하지 않지만, **설정된 대상으로 최소한의 Speech/OpenAI 요청을 보내므로 통신과 소액 과금이 발생할 수 있습니다**.
- 부족한 역할을 직접 부여할 수 없다면 표시된 정보를 관리자에게 전달하세요. `--assign-roles`를 가볍게 사용하지 마세요.

## 4. 원본 추가 후 P4 선택하기

1. 「프로젝트 이름」을 입력하고 **새 프로젝트**를 누릅니다.
2. **파일 선택**을 누르거나 동영상을 끌어서 놓습니다.
3. 원본 이름, 길이, 해상도, 음성 유무를 확인하고 각 원본의 권리 확인에 체크합니다.
4. **P4 클립 추출(긴 영상→30초)**을 선택합니다. 파란 테두리가 선택 상태입니다.
5. 시리즈는 끄고, 필터링은 **표준**으로 둡니다. 첫 시도에는 BGM이나 오프닝이 필요 없습니다.
6. 설정/화면 아래의 전송 대상과 예상 비용을 읽고 **후보 3개 만들기**를 누릅니다.

![원본·패턴·생성의 실제 화면](../../../users-guide/images/screen-project.svg)

이 화면은 3열입니다. 열 내부를 스크롤하면 아래 항목이 보입니다. 위쪽의 6단계 표시는 진행 상황을 나타내며 클릭해서 화면을 건너뛰는 탭이 아닙니다.

## 5. 후보를 확인하고 필요하면 수정하기

생성 화면에는 전체 진행률과 현재 처리 단계의 진행률이 표시됩니다. 후보가 만들어지면 동영상을 재생해 다음을 확인하세요.

- 원래 발언의 의미가 달라지지 않았는지. 단독으로 봐도 이야기가 통하는지.
- 자막 오탈자, 고유명사, 숫자, 가독성.
- 얼굴이나 화면에서 보고 싶은 부분, 음량, 발화 경계.
- QA의 「실패」「경고」「미실행」. **미실행은 통과가 아닙니다**.

후보의 **확인·수정**을 엽니다. 글자를 고쳤다면 입력란 밖으로 포커스를 옮겨 변경을 반영하고 **미리 보기 업데이트** 후 다시 확인하세요. 전사의 오인식을 수정하면 자막이 다시 생성되므로, 수동 자막 수정 전에 처리하세요.

![확인·수정의 실제 화면](../../../users-guide/images/screen-review.svg)

## 6. 내보내고 저장하기

다음 중 하나를 선택합니다.

- **한 편 바로 내보내기**: 「확인·수정」의 **이 내용 승인 후 내보내기(1080×1920)**(동영상이 여러 개라면 **이 한 편만 지금 내보내기(1080×1920)**). 현재 내용을 승인한 뒤 내보냅니다. 하드 QA와 필요한 AI 문장 승인도 충족해야 합니다.
- **여러 동영상을 하나씩 확인하고 한꺼번에 내보내기**: 「확인·수정」에서 **승인 후 다음 동영상으로**를 눌러 차례대로 확인하고, 마지막 동영상에서 **승인 후 내보내기로 이동** → 내보내기 목록의 **선택한 동영상 내보내기**를 누릅니다. 도중에 **이 내용으로 승인 후 후보로 돌아가기**를 누르면 후보 목록의 **확인 진행 상황**에서 남은 항목을 볼 수 있습니다. 변경하면 다시 승인해야 합니다.

내보내기 목록에서는 완료된 동영상별로 완성 파일을 재생·탐색해 확인할 수 있습니다. 동영상 파일의 절대 경로를 확인하고 **경로 복사** 또는 **폴더 열기**로 저장 위치에 접근하세요. 개별 완료 화면에서도 같은 조작과 최종 QA 확인이 가능합니다.

![내보내기 완료의 실제 화면](../../../users-guide/images/screen-export.svg)

| 파일 | 용도 |
|---|---|
| `.mp4` | 자막을 영상에 삽입한 게시용 동영상. 게시 전에 끝까지 재생해 확인 |
| `.srt` | 시간 정보가 있는 자막. 외부 자막을 지원하는 게시 대상·편집 도구에서 사용 |
| `.ass` | 글꼴·위치·장식이 포함된 자막 렌더링 데이터 |
| `.editplan.json` | 컷, 텔롭, 소리, 삽입물의 편집 기록. 개발·재현용 |
| 썸네일 이미지 3장 | 게시용 이미지 후보. 직접 선택 |
| `.metadata.md` | 제목·설명·해시태그 등의 제안. 사실 확인 후 게시 입력란에 수동으로 옮기기 |
| `.post.json` | 완료 화면의 「게시용 글」과 같은 내용(YouTube 설명·Viva Engage 게시글·챕터). `.metadata.md` 끝에도 붙여 넣기 쉬운 형태로 포함 |

내보내기 목록과 완료 화면의 **게시용 글(복사해서 붙여 넣기)**에는 저장된 YouTube 설명, Viva Engage 게시글, `00:00 장 제목` 형식의 챕터가 나열되며 각각의 **복사** 버튼으로 붙여 넣을 수 있습니다. 아직 생성하지 않았다면 **게시용 글 만들기**를 누르세요. **기타 결과물·미리 보기**를 펼치면 자막·메타데이터·편집 계획 내용과 썸네일을 확인하고 각 파일을 열거나 저장할 수 있습니다.

- 챕터 시간은 내보낸 동영상의 실제 시간입니다(오프닝·카드 분량도 반영). YouTube 조건(00:00부터 시작·3개 이상·각 10초 이상)을 충족하지 않으면 붙이지 않습니다. 3분 이내의 세로 영상은 Shorts로 취급되어 재생 막대에 챕터가 나타나지 않을 수 있습니다.
- 글은 AI가 전사를 바탕으로 만들며, 발화에 없는 숫자·가타카나 단어·영문 이름, URL, 가린 단어를 자동으로 제외합니다(한자 고유명사까지는 판별하지 못합니다). 제외 이유는 화면에 표시됩니다. LLM을 사용하지 않는 설정에서는 서식으로 만듭니다.
- **다른 제안 만들기**로 이전과 다른 관점의 제안을 다시 만들 수 있습니다. 화면은 저장된 글의 읽기 전용 표시입니다. 필요한 수정은 복사 후 붙여 넣을 곳에서 하세요. 복사에 실패하면 표시된 글을 선택하고 Ctrl+C를 사용하세요.

SRT와 영상에 삽입된 자막을 동시에 표시하면 게시 대상에 따라 자막이 이중으로 보일 수 있습니다. 게시 대상의 표시 방식을 선택하세요. 앱은 게시·공개·시리즈 URL 자동 설정까지 수행하지 않습니다.

종료하려면 시작 터미널에서 Ctrl+C를 누릅니다. 다음에는 프로젝트 목록에서 열면 마지막으로 표시했던 프로젝트 설정, 생성, 후보, 확인·수정, 내보내기 단계에서 재개합니다. 참조 대상이 없어졌다면 복원 가능한 이전 단계를 표시합니다. 백업은 [문제 해결](troubleshooting.md#저장과-백업)을 참조하세요.
